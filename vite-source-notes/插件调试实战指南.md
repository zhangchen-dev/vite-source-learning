## 二、两种调试模式：dev watch vs 单次 build

### 模式 A：dev watch 模式（推荐，改源码自动编译）

启动 vite 本体的 watch 编译：

```bash
# 终端 1：启动 vite 本体的 watch 编译
cd d:\File\前端经典项目\vite
pnpm dev
# 输出：
# tsdown vite (vite) started building in watch mode
# ✔ built in 2.3s
```

然后另开一个终端跑 playground：

```bash
# 终端 2：跑任何 playground
cd d:\File\前端经典项目\vite\playground\define
pnpm run dev      # dev 模式（最常用）
# 或者
pnpm run build    # build 模式（看 resolveFileUrl 等 build 专属钩子）
```

**改了 src/node/plugins/*.ts 后保存，watch 模式会自动重新编译 → 下次 playground 运行就会用到新代码。**

### 模式 B：单次 build 模式（快速验证）

如果不想一直开 watch，可以手动 build：

```bash
# 只 build vite 本体（比全量 build 快很多）
cd d:\File\前端经典项目\vite
pnpm --filter vite run build
```

## 三、推荐的 playground 对照表

按你想调试的插件选对应的 playground：

| 想调试的插件 | 推荐 playground | 理由 |
|-------------|----------------|------|
| **resolve** | `playground/resolve/` | 专门测 resolve 各种场景 |
| **define** | `playground/define/` | 直接测 define 替换 |
| **asset** | `playground/assets/` | 有 .svg / .png / .woff2 / .txt?raw 各种资源 |
| **css** | `playground/css/` | 专门测 CSS 处理 |
| **importAnalysis** | `playground/define/` 或 `playground/hmr/` | 任何 playground dev 模式都能触发 |
| **worker** | `playground/worker/` | Worker + file:// URL |

## 四、在插件代码里加调试打印

### 最常用：console.log 直接打

在源码里加，然后看 playground 的终端输出：

**示例：在 asset 插件 load 钩子入口加打印**

```typescript
// packages/vite/src/node/plugins/asset.ts 第240行附近
async handler(id) {
  console.log('[asset:load]', { id, isBundled: this.environment.config.isBundled })  // ← 加这行

  // raw requests, read from disk
  if (rawRE.test(id)) {
```

**示例：在 resolveFileUrl 里打印**

```typescript
// packages/vite/src/node/plugins/asset.ts 第305行附近
resolveFileUrl({ fileName, chunkId, format, urlId }) {
  console.log('[asset:resolveFileUrl]', { fileName, chunkId, format, urlId })  // ← 加这行
```

**示例：在 resolve 插件里打印**

```typescript
// packages/vite/src/node/plugins/resolve.ts 里 oxcResolvePlugin 返回的 resolveId 钩子
resolveId: {
  filter: { id: /.*/ },  // 不加 filter，所有 id 都进来
  handler(id, importer) {
    console.log('[resolve:resolveId]', { id: id.slice(0, 80), importer: importer?.slice(0, 60) })
    // ... 原有逻辑
  },
},
```

### 进阶：用 console.count / console.group 让输出更清晰

```typescript
let callCount = 0

transform(code, id) {
  if (id.includes('main.js')) {
    console.group(`[define:transform] #${++callCount}`)
    console.log('id:', id)
    console.log('code length:', code.length)
    console.log('前100字符:', code.slice(0, 100))
    console.groupEnd()
  }
}
```

### 用 import.meta 打印到浏览器 Console（dev 模式）

在 transform 钩子里注入打印语句，让浏览器控制台也能看到：

```typescript
transform(code, id) {
  if (id.endsWith('/main.js') || id.endsWith('/index.js')) {
    return `console.log('[vite-plugin-debug]', ${JSON.stringify(id)});\n${code}`
  }
}
```

## 五、实际操作步骤（每次调试）

```
Step 1：开终端 1，启动 vite watch
  cd d:\File\前端经典项目\vite
  pnpm dev
  （保持运行，不要关）

Step 2：在 VS Code 里打开插件源码，加 console.log

Step 3：开终端 2，跑 playground
  cd d:\File\前端经典项目\vite\playground\define
  pnpm run dev        ← 或者 build

Step 4：终端 2 会显示插件里加的 console.log 输出

Step 5：改源码 → 保存 → 终端 1 自动重编译 → 终端 2 重新触发就能看到新输出

Step 6：调完了 → 删掉 console.log（或者用 git checkout 还原）
```

## 七、调试 build 专属钩子

build 专属钩子（`resolveFileUrl`、`renderChunk`、`generateBundle`）在 dev 模式下**不会执行**，必须用 build：

```bash
cd playground\assets
pnpm run build
# 终端会打印 resolveFileUrl 等钩子的输出
```

dev 专属钩子（`transform` 里的 importAnalysis、watchChange）在 build 模式下不会执行。
